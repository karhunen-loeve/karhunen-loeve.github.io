Thomas Stephan

Computer vision engineer. I write Rust, and I write about the bugs a compiler should have caught.

I have spent a good part of my career chasing bugs that were never really bugs: a channel order nobody wrote down, a gamma curve everyone assumed, a pyramid level that drifted half a pixel. My interest is in making that whole class of mistake impossible — encoding what a number means into its type, so the compiler objects on the line where the mistake happens instead of a reviewer noticing three months later.

The fix is not more care. Care doesn't scale.

What follows is organised by topic. Each post takes one problem, shows it small enough to be undeniable, then shows the same problem where no human is looking — inside a tensor, inside a production pipeline. The payoff is always a compile error.

Hardening Computer Vision with a Proper Type System

Three classic computer vision bugs that have each cost the field twenty years. None of them is a logic bug. Every one of them is a type bug — correct functions exchanging values whose meaning was never written down.

  1. Part 1

    The Blue Face Bug

    Your camera says blue-green-red. Your model says red-green-blue. The bytes in between say nothing at all.

    Beginner · channel order, Bgr8, ColorSwap

  2. Part 2

    128 Is Not the Middle

    Average a black pixel and a white pixel. You wrote (0 + 255) / 2 and got 128 — and that answer is wrong by a margin you can see from across the room.

    Beginner–intermediate · gamma and interpolation, Srgb8, SrgbGamma

  3. Part 3

    Climbing the Pyramid

    Sizes that stop matching, two “scales” that aren’t the same thing, and coordinates that quietly drift half a pixel per step.

    Intermediate · scale space, pyramids, half-pixel drift
